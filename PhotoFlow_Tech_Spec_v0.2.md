# PhotoFlow — техническое задание и архитектура

> Архивное проектное предложение. Текущая реализация описана в [STATUS](docs/STATUS.md). Локальные пути в этой публичной копии обезличены.

**Версия:** 0.2, 25 октября 2026 года  
**Статус:** проектное предложение; исходный код и работающий прототип ещё не созданы.  
**ОС:** Windows 11 x64.  
**Локальная рабочая папка (предлагаемая, не создана):** `PhotoFlow/`.

## 0. Главное изменение относительно версии 0.1

**Основной сценарий — отбор до импорта:** подключить iPhone или Android по USB → просматривать доступные медиафайлы прямо на устройстве → группировать и фильтровать → отмечать звёздочкой или галочкой → импортировать лишь выбранное в указанную папку Windows. Полное предварительное копирование медиатеки **не требуется**.

**Физическое ограничение:** просмотр без считывания каких-либо данных невозможен. PhotoFlow получает список файлов и, если устройство позволяет, маленькие миниатюры; может временно загружать данные для просмотра или декодирования RAW. Временный кэш отличается от осознанного импорта оригиналов. При отсутствии у USB-устройства отдельной миниатюры полный файл иногда необходим для формирования превью. Режим «Никогда не скачивать целые оригиналы ради превью» должен отключать такую загрузку и показывать заглушку.

## 1. Пользовательские сценарии

### Сценарий A. Просмотр напрямую с телефона
1. Подключить устройство кабелем передачи данных, разблокировать, подтвердить доверие или выбрать USB-режим «Передача файлов».
2. В боковой панели выбрать обнаруженное устройство.
3. Приложение сразу показывает доступные найденные объекты и ход дальнейшего сканирования (`найдено 1 200…`, `миниатюр 430…`).
4. Объекты постепенно объединяются в каталог с датами, размерами и расширениями, без копирования оригиналов.
5. Виртуализированная сетка отображает миниатюры сначала для видимых карточек, затем для соседних; при прокрутке отменяет неактуальные запросы.
6. Сортировать по имени, дате съёмки, дате изменения, размеру, типу и разрешению; группировать по дню, месяцу, году, формату и папке.
7. Раскрыть полноэкранный просмотр с быстрым переключением; если оригинал нужен, показать статус временной загрузки и возможности устройства.

### Сценарий B. Быстрый массовый отбор
- Галочка = выбор для импорта; звезда = постоянное избранное PhotoFlow.
- Клик по галочке, Ctrl+клик, Shift+клик по диапазону, Ctrl+A = выбрать всю видимую/отфильтрованную выборку (UI явно указывает охват), Ctrl+Shift+I = инвертировать.
- «Выбрать все за день/месяц», «Выбрать все RAW», «Выбрать все ★», «Выбрать только новые», «Выбрать по диапазону дат».
- Панель отбора: число выбранных, суммарный размер, оценка свободного места на диске, назначение, статус дублей.
- Сохранённые подборки для следующего подключения, даже если устройство отсоединено.
- После импорта отметка «Уже импортировано» без удаления на телефоне.
- Для тысяч выбранных файлов операция «Выбрать все совпадающие с фильтром» должна работать по базе данных, а не только по созданным визуальным карточкам.

### Сценарий C. Импорт
1. Отобразить точный состав выбранного набора перед началом, включая RAW+JPEG пары и Live Photos, если они обнаружены.
2. Указать папку Windows и шаблон каталогов (`Год/Месяц` или всё в одну папку).
3. Очередь запускает потоковую передачу оригиналов только для выбранных файлов, пишет во временные файлы `.part`.
4. После корректного завершения каждого объекта проверить размер, выполнить `SHA-256` при необходимости и атомарно переместить в конечное имя.
5. На дубликатах предложить `пропустить / сохранить с суффиксом / проверить вручную`.
6. Отключение устройства не удаляет очередь: уже перенесённые объекты сохранены, незавершённый файл повторно переносится после повторного подключения. **Докачка с определённого байта возможна только при фактической поддержке повторного позиционирования потока устройством; иначе перезапуск конкретного файла.**
7. Исходные медиафайлы на телефоне не изменять и не удалять в MVP.

### Сценарий D. Работа с локальными файлами
- Подключение существующих каталогов в режиме «индексировать без копирования».
- Импортированные файлы доступны без телефона.
- Избранное работает одинаково для локальных и внешних объектов; не требует физического перемещения файлов.

## 2. Матрица источников

| Источник | Подключение | Просмотр до импорта | Ограничения |
|---|---|---|---|
| iPhone / iPad | USB, WPD/PTP-совместимый доступ, проверяется на реальном устройстве | Если медиа доступны Windows и удаётся получать превью или ресурсы | Разблокировка и подтверждение доверия; состав доступных файлов и миниатюр зависит от iOS/драйвера. Оптимизация iCloud может означать отсутствие оригинала на устройстве. Полные альбомы Apple Photos не гарантируются. |
| Android | USB MTP через WPD, выбран режим «Передача файлов» | Да, для файлов, опубликованных устройством | Превью по MTP может отсутствовать; производительность зависит от телефона и USB. Некоторые системные/private-альбомы недоступны. |
| Локальная папка / карта памяти | Файловая система Windows | Да | Сканирование обычных файлов без копирования. |
| Беспроводное подключение | **Возможный следующий этап** | Не часть MVP | Потребуется отдельный протокол или мобильный компаньон; нельзя обещать функции обычного USB по Wi-Fi. |

Индексы метаданных не эквивалентны доступу ко всей системной галерее телефона: каталог показывает только то, что устройство предоставляет через подключение.

## 3. Стек

| Область | Предпочтение | Примечания |
|---|---|---|
| Desktop | C# / .NET 10 + WinUI 3 | MVVM, виртуализация ItemsRepeater или другого проверенного grid-контрола |
| Хранилище | SQLite с WAL, Microsoft.Data.Sqlite | Каталог, флаги, закладки, очередь и индексы; WAL не должен размещаться на телефоне |
| Метаданные | MetadataExtractor + WPD properties | Дата съёмки с приоритетом EXIF/QuickTime при доступе, иначе явно маркированный fallback |
| RAW | LibRaw (изолированный нативный модуль) | DNG, CR2, CR3, NEF, ARW, RAF, ORF, RW2 и др. по реальной матрице LibRaw/камер; извлечение embedded preview и декодирование по необходимости |
| HEIC/JPEG/PNG | WIC + подходящие HEIF-кодеки/резервный декодер | Требования к системным кодекам проверять; не предполагать их наличие |
| Видео | Media Foundation | Миниатюры и полноэкранное воспроизведение поддерживаемых кодеков, ограничения явно показывать |
| USB | Windows Portable Devices (WPD) через COM-адаптеры | `AndroidMtpSource` и `AppleUsbSource` независимо тестируются, хотя общий транспорт возможен |
| Логи | Microsoft.Extensions.Logging | Ошибки и диагностика без выгрузки в облако |
| Тесты | xUnit; устройства в интеграционных тестах | Матрица телефонов/RAW и тестовый каталог |

**Лицензии:** при использовании LibRaw проверить актуальные условия LGPL-2.1/CDDL, сборку и распространение нативной библиотеки. Дополнительные Windows HEIF/HEVC компоненты нельзя безусловно предполагать установленными.

### Интерфейс абстрактного источника

```csharp
public interface IMediaSource : IAsyncDisposable
{
    Task<SourceCapabilities> GetCapabilitiesAsync(CancellationToken ct);
    IAsyncEnumerable<MediaDescriptor> EnumerateAsync(CancellationToken ct);
    Task<Stream?> TryOpenThumbnailAsync(string sourceItemKey, CancellationToken ct);
    Task<Stream> OpenOriginalAsync(string sourceItemKey, CancellationToken ct);
    Task<bool> ExistsAsync(string sourceItemKey, CancellationToken ct);
}
```

Контракт иллюстративный: реальный WPD может выдавать потоки с ограничениями seek/считывания и не все устройства поддерживают `TryOpenThumbnailAsync`. Не реализовывать интерфейс через `System.IO.File`, если объект MTP не смонтирован как нормальный файловый путь.

### Стратегия превью: три уровня
1. **A — устройство отдаёт thumbnail:** читать ресурс `WPD_RESOURCE_THUMBNAIL`, если заявлен и доступен.
2. **B — устройство отдаёт поток, возможно чтение небольших частей:** пытаться извлечь embedded preview из JPEG/RAW только если формат, транспорт и API допускают это эффективно.
3. **C — thumbnail отсутствует:** по настройке пользователя (а) временно скачать нужный оригинал в лимитированный кэш, декодировать и удалить по LRU, (б) не скачивать полный файл, показывать placeholder до импорта.

Для просмотра в полный размер также потребуется чтение достаточного объёма данных; оригиналы не добавляются в постоянную фототеку автоматически.

Показ миниатюр начинается с видимой области, далее соседние элементы; очереди `visible > user-opened > near-viewport > background` с отменой невидимых задач. Вести ограниченный бюджет RAM и временного диска, например настраиваемый диск-кэш по умолчанию до 2 ГБ (не обещание фактического объёма на устройстве).

## 5. SQLite — расширенная схема (структурный набросок)

```sql

  id INTEGER PRIMARY KEY,
  source_kind TEXT NOT NULL,            -- apple_usb, android_mtp, local

  width INTEGER,
  height INTEGER,
  duration_ms INTEGER,
  mime TEXT,

CREATE TABLE import_jobs (

);
CREATE TABLE import_job_items (
  job_id INTEGER NOT NULL,
```

**Важная специфика идентификаторов:** WPD object ID может быть непостоянен. Сопоставлять объект при новом подключении по устойчивым признакам: устройство, относительный путь, имя, размер, дата, при необходимости дополнительная выборочная проверка. Никогда не считать равные имена равными фотографиями. Хеш исходного файла не вычислять для каждого объекта перед импортом (это потребовало бы передавать весь массив). Для кандидатов в дубликаты использовать дешёвые метаданные, после переноса — полное сравнение.

**Даты:** имя файла/дата изменения не эквивалентны дате съёмки. Полная EXIF-дата может быть недоступна по USB без чтения файла. Пока идёт индексирование, интерфейс явно показывает предварительную хронологию, затем уточняет даты; нельзя обещать идеальную сортировку всего устройства мгновенно.

## 6. Производительность и большие коллекции

**Целевые тестовые объёмы:** 1 000 / 10 000 / 50 000 элементов, отдельно USB iPhone и Android. Цели — *инженерные критерии, не измеренные показатели*: 

- Начать выдавать первые найденные файлы до завершения полного перечисления.
- Не создавать все карточки UI для 50 000 объектов — виртуализировать сетку.
- Не читать оригиналы всех файлов для поиска или списка.
- Избранное и выбор 10 000+ объектов должны быть операциями базы данных и не блокировать UI.
- Сортировать и группировать через SQL с индексами, а не `ObservableCollection.OrderBy()` на UI-потоке.
- Для WPD по умолчанию использовать консервативную последовательную передачу; конкурентность выше 1 разрешать только после бенчмарков по устройству. Не перегружать телефон сотнями параллельных обращений.
- Импортировать много файлов через сохраняемую очередь, с прогрессом по файлам и байтам, пропуская уже завершённые.
- Ограничить дисковый кэш, поддержать очистку; при отключении устройства карточки и сохранённые звёздочки остаются в каталоге, недоступный оригинал помечается как offline.

Метрики, которые **требуется измерить**: время появления первого экрана; полное перечисление 10к/50к файлов; доля доступных device thumbnails; скорость прокрутки с тёплым и холодным кэшем; скорость импорта 100/1000 файлов; поведение при отключении и повторном подключении. Универсальную скорость без реальных тестов не обещать.

## 7. Интерфейс

Левая панель: `Подключённые устройства`, `Моя библиотека`, `Избранное ★`, `Очередь импорта`, `Сохранённые подборки`, `Настройки`.

Верхняя панель: `Группировать`, `Сортировать`, `Направление`, `Фото/Видео/RAW`, `Интервал дат`, `Поиск`, `Только ★`, `Только не импортированные`.

Центр: виртуализированная сетка с миниатюрами и статусами (`RAW`, `Видео`, `★`, `✓`, `Импортировано`, `Превью недоступно`).

Правая/нижняя панель: выбранное количество, суммарный размер, место назначения, `Импортировать выбранное`.

Полноэкранный просмотр: стрелки навигации, `Пробел` выделить/снять выделение, `F` или `S` добавить/убрать звезду (назначение закрепить в настройках), метаданные, 100%-увеличение, переключение между оригиналом и встроенным RAW-preview, если доступно.

Избранное PhotoFlow — **собственная локальная метка**, не запись в native избранное iOS/Android. Не требовать вмешательства в системные альбомы телефона.

## 8. RAW и специальные случаи

- RAW: DNG, CR2, CR3, NEF, ARW, RAF, ORF, RW2 и другие, **только если конкретный вариант/камера поддержаны выбранной версией LibRaw**.
- Для RAW предпочтителен embedded JPEG preview; полное RAW-декодирование выполнять только по запросу и при наличии достаточного файла. RAW нельзя декодировать из отсутствующих байтов.
- RAW+JPEG (с одинаковым stem/кадром): опционально визуально группировать в одну карточку, но в базе и импорте сохранять обе независимые сущности и явно выбирать, что копировать.
- Live Photos: по возможности связывать HEIC/JPEG и MOV по доступным метаданным; не удалять/не объединять необратимо, пока не проверен формат.
- HEIC/HEVC: проверить наличие кодеков; при отсутствии предложить установить необходимые компоненты или включить резервный декодер, без автоматического изменения оригинала.
- Дубликаты: имена `IMG_0001` переиспользуются, даты могут быть с ошибками, а перекодированные фото иметь другое содержимое. Быстрый отбор и точное определение дубликатов — отдельные задачи.
- iCloud/Google Photos: виртуальные облачные элементы могут не быть доступны через USB без предварительной загрузки на телефон. Не обещать доступ к облаку через USB.

## 9. Этапы реализации, зависимости и проверки

### P0 — технологический прототип устройств (самый рискованный)
- Консольный WPD-сканер: обнаружение iPhone и Android; отображение ID, имени, размера, типа, времени; без переноса оригиналов.
- Проверка получения `WPD_RESOURCE_THUMBNAIL` на реальных устройствах и возможности открыть выбранный файл.
- Зафиксировать: доступно ли 100/1000/10 000 объектов; какие даты и миниатюры приходят; сколько времени занимает индексация.
- **Контрольная точка:** если iPhone не отдаёт миниатюры, решаем — разрешить временный предпросмотр с чтением оригинала или создавать отдельный iOS-компаньон в будущей версии. Не маскировать ограничение.

### P1 — галерея без импорта
- WinUI 3 UI; виртуализация и SQLite, локальная папка и хотя бы один рабочий USB-адаптер.
- Индексация без полного копирования, сортировка по дате/имени/типу/размеру, фильтры, группировка.
- Избранное ★ и сохранение его после перезапуска и отключения.
- Первый экран начинает наполняться до завершения общего сканирования.

### P2 — массовый отбор и RAW
- Виртуализированная сетка, Ctrl/Shift, «весь месяц», «все RAW», «все избранные».
- Добавить LibRaw, embedded preview и представление RAW+JPEG, fallbacks.
- Режим строгого запрета временного скачивания полных оригиналов ради миниатюр.

### P3 — очередь выборочного импорта
- Сохранение выбранных объектов, оценка объёма, потоковая передача выбранного, проверка целостности.
- Обработка отключения, восстановления, конфликтов имён, вероятных дублей.
- Нельзя удалять файлы телефона в этой версии.

### P4 — тестирование и установщик
- 10к/50к фото, разный iPhone и минимум два Android разных производителей, популярные RAW, режим iCloud «Оптимизация хранилища».
- Скорость первых миниатюр, прокрутка, память, кэш, температурная и USB-устойчивость.
- Инсталлятор и подробная диагностика проблем устройств.

**Приоритет:** P0 раньше сложного UI. Именно поведение реальных USB-устройств определяет пригодность основного сценария.

## 10. Минимальные критерии приёмки

- [ ] Галерея Android MTP показывает файловый список до полного копирования.
- [ ] Галерея iPhone показывает реально доступные Windows файлы до полного копирования; ограничения зафиксированы отдельно.
- [ ] Приложение не скачивает все оригиналы автоматически ни при подключении, ни при сортировке.
- [ ] Режим «Только миниатюры, без загрузки целых файлов ради превью» соблюдается.
- [ ] Фильтры и сортировка действуют на полный проиндексированный набор, а не только на видимые карточки.
- [ ] ★ сохраняется после закрытия приложения и отключения/подключения.
- [ ] Ctrl/Shift, отбор целого месяца, типовой отбор RAW, выбор всех совпадений с фильтром работают при 10к+ файлах.
- [ ] RAW DNG + по меньшей мере два актуальных камерных RAW проверены реальными тестовыми файлами.
- [ ] Импортированы только выбранные оригиналы; исходники на телефоне остаются неизменны.
- [ ] После USB-обрыва ранее завершённые объекты не копируются повторно, а незавершённый безопасно повторяется.
- [ ] Значение «дата съёмки» сопровождается источником/уверенностью; дата импорта не подменяет дату съёмки.
